# Wait Modernization — Overview and Shared Contracts

> **For agentic workers:** This is not an executable plan. It is the **single source of truth** for names, paths, wire formats, schema, env vars and decisions that plans 01–06 share. Read it before executing any plan. When a plan and this overview disagree, stop and ask the user. Execute the plans in the order in §4. Each plan says which plans it needs first.

**Goal:** Turn Wait into a modern app for personal stock watching:
- iOS 17 SwiftUI, TCA 1.x, and a local Swift package.
- A target-price ladder with a 0–100 "temperature", borrowed from the `market-temperature` skill.
- Cached, rate-limit-safe market data.
- A small TypeScript backend that syncs the watchlist across devices and pushes a notification when a stock crosses one of its ladder prices after the US close.

## 1. Goals and non-goals

### Goals
1. **Modernize the iOS app.**
   - iOS 17 and watchOS 10 minimum.
   - All modules in one local SwiftPM package (`WaitKit`). The Xcode project is generated by XcodeGen.
   - TCA 1.26.x, with every screen written as a `@Reducer`.
   - A refreshed SwiftUI UI built on Swift Charts.
2. **Make market data rate-limit-safe.**
   - Caches on the device and on the server, aware of market hours.
   - Requests coalesced, with a per-provider token bucket and cooldown after a 429.
   - No provider keys on the device.
3. **Build a backend** (`/Users/ckai/code/Wait/server`, same repo):
   - Anonymous identity.
   - Watchlist sync: notes, favorites, ladder, checklist.
   - A daily job after the close that checks each ladder and sends an APNs push when a stock crosses a price.
4. **Fix the widget and watch.**
   - The widget reads the real watchlist from the app group.
   - The watch shows the real watchlist, using the shared `Domain` types plus a WCSession snapshot.

### Non-goals
- Public App Store distribution. Data licensing is personal-use only (see §6.4).
- Sign in with Apple or App Attest.
- Intraday alerts, or anything more often than once a trading day.
- Automatically adjusting anchors after a stock split. A guard skips alerts after a move of more than 50%.
- Syncing the checklist template across devices. Each stock's checklist does sync.
- Watch complications and an independent watch app (the watch never touches the network).
- HKEX and OTC symbols. Search is filtered to US listings.
- Moving to Vercel "Schedules" (beta). We stay on Vercel Cron.

The research is in §6. |
| D13 | The server's token bucket and caches live in Postgres. No Upstash. | One fewer service. One atomic SQL statement works over the Neon HTTP driver, and it can be tested with PGlite. |
| D14 | Auth is the same as Resignal: an anonymous UUID, then `POST /api/auth/register`, then an HS256 JWT valid for 7 days. The UUID is kept in the Keychain with `kSecAttrSynchronizable`. | User decision. iCloud Keychain carries the same identity to the user's other devices, and it survives a reinstall. |
| D15 | Sync is offline-first, last-write-wins per item, keyed by `(user_id, symbol)`, with a `(version, symbol)` cursor. Deletes are kept as tombstones. | The simplest design that handles several devices and the first upload (§8.5). |
| D16 | Alerts are **directional**. A push is sent only when an item moves down into `BUY_ZONE` or `DEEP_BUY`, or up into `TRIM` or `SELL`. A stock's first evaluation records its status without a push. At most one push per item, status and trading day. | User decision (§7.3). |
| D17 | Vercel Cron `0 22 * * 1-5` (UTC) | 22:00 UTC is after the close in both EST and EDT, even with Hobby's ±59 min jitter. Hobby allows one cron run a day. |
| D18 | Backend tests run routes through `app.inject` against a mock container, and repository SQL against **PGlite** (in-process Postgres). An optional `test:neon` script runs the same suite against a Neon branch. | Real SQL needs no credentials. |
| D19 | The backend lives in the monorepo at `server/` and follows the conventions in `/Users/ckai/code/Resignal-backend`, plus fixes for that repo's known gaps (§8.1) | User decision. |
| D20 | All prices travel as **decimal strings** in JSON and are compared as `Decimal`/`NUMERIC`. Temperature is a `Double`. | Avoids Double drift (e.g. 3.133 becoming 3.13299…). |
| D21 | Every timestamp that is persisted or synced is **truncated to whole milliseconds** when it is created | The server echoes ISO strings with millisecond precision. Without truncation, acknowledgment equality would never match (§8.5). |

## 6. Market data and rate limits (investigation result)

### 6.1 Problems with the current setup
1. **Twelve Data Basic plan:** the terms say it's for *"Internal non-display usage… cannot be displayed to users, shared externally, or used in production systems"* (https://twelvedata.com/pricing; terms §2.3(l): no commercial use of free-tier data).
   - Limits: 8 credits/min and 800/day.
   - A batch `/quote` call costs 1 credit per symbol (https://support.twelvedata.com/en/articles/5615854-credits), so batching saves nothing.
   - The key is hard-coded in `Wait/Networking/URLDomain.swift` and copied into the watch app, so **every install shares one quota**.
2. **Alpha Vantage free plan:** 25 requests/day, and `OVERVIEW` is now marked Premium (https://www.alphavantage.co/documentation/).
3. **The app calls too often:**
   - Every Waitlist `onAppear` (launch, tab switch, back from details) refetches all quotes.
   - Every visit to a stock's details makes 5 `time_series` calls (one per range) plus 1 `OVERVIEW` call.
   - Nothing has a TTL.
   - Example: 10 stocks and 3 detail visits ≈ 55 Twelve Data credits and 3 Alpha Vantage calls.
4. **Apple has no stock-quote API.** FinanceKit covers Apple Card and Wallet only.

### 6.3 Proposal (what plans 02, 04 and 06 build)
1. **The device calls only our backend** (plan 04). Provider keys live in Vercel environment variables.

2. **Device cache** (`CachingMarketDataClient`, plan 02).
   - **Storage:** an in-memory map plus a disk cache under `Library/Caches/marketdata/`.
   - **Policies:**

     | Policy | Behavior |
     |---|---|
     | `.useCache` | Return fresh data from the cache. Otherwise fetch, and if the fetch fails, return a stale entry up to 7 days old. |
     | `.reload` | Always fetch, with the same stale fallback. |
     | `.cacheOnly` | Return any cached entry, or throw `.notCached`. |

   - **Coalescing:** identical in-flight requests are merged. For quotes, only the symbols that are missing or stale are fetched.
   - **429 cooldown:** after a 429, all calls behave as `.cacheOnly` for `retryAfter`, or 60 s if none is given.
   - **TTLs** (`CacheTTL` plus `MarketCalendar`: America/New_York, Mon–Fri 09:30–16:00, no holiday table on the device):

     | Kind | Market open | Market closed |
     |---|---|---|
     | quote | 60 s | 5 min within 30 min after the close; otherwise until the next open |
     | series 1D | 5 min | until the next open |
     | series 1W | 15 min | until the next open |
     | series 1M / 1Y / 5Y | next close + 2 h | next close + 2 h |
     | search | 24 h | 24 h |
     | profile | 7 d | 7 d |

   - **Screens:** each screen reads `.cacheOnly` first so it renders immediately, then `.useCache`. Pull-to-refresh uses `.reload`. The chart fetches only the selected range (1Y by default), not all 5.
   - **Stopgap until plan 04:** a Twelve Data adapter.
     - Quotes are chunked 8 symbols per call, and each symbol is decoded on its own.
     - HTTP 200 with `code: 429` in the body is treated as `.rateLimited`.
     - `timezone=UTC` is always sent.

3. **Server cache** (plan 04).
   - Tables: `quote_cache`, `history_cache`, `profile_cache`, `search_cache`, each with `expires_at`. Entries are shared per symbol across all users.
   - Server TTLs: quotes 3 min while the market is open (until the next open when closed); `daily5y` until the next close + 2 h; search 7 d; profile 7 d; metrics 1 d.
   - In-process promise coalescing.
   - Stale fallback: the response carries `stale: true`. If nothing is cached, the server returns 503 `UPSTREAM_RATE_LIMITED` with `Retry-After`.

4. **Token buckets in Postgres** (`rate_buckets`, one atomic `INSERT … ON CONFLICT … WHERE … RETURNING`). A provider 429 blocks that provider's key for `Retry-After` (or 60 s).

   | Key | Capacity | Refill per second |
   |---|---|---|
   | `provider:finnhub` | 30 | 1 |
   | `provider:tiingo:hour` | 50 | 50/3600 |
   | `provider:tiingo:day` | 1000 | 1000/86400 |
   | `provider:alpaca` | 100 | 200/60 |
   | `provider:massive` | 5 | 5/60 |
   | `register:ip:<ip>` | 20 | 20/60 |

## 7. Domain contracts (Swift `Domain` and TS `server/src/domain`)

### 7.1 Status strings, rungs, bands (identical on both sides)
- `LadderStatus` raw values: `DEEP_BUY`, `BUY_ZONE`, `WATCH`, `AT_OR_ABOVE_FAIR`, `TRIM`, `SELL`, `NO_ANCHORS`.
- Rung keys (JSON): `buyLow`, `buyHigh`, `fair`, `trim`, `sell`. Scores: 10, 30, 50, 80, 95.
- `TemperatureBand` keys: `freezing` (<20), `cold` (<40), `neutral` (<60), `warm` (<80), `hot` (≥80).
- `ChartRange` raw values: `1D`, `1W`, `1M`, `1Y`, `5Y`.

### 7.2 Ladder algorithm (reference: market-temperature `scripts/watchlist.py` `build_knots`, `classify_status`; `score.py` `interpolate_knots`)
1. **Validation:**
   - Every present anchor must be > 0, otherwise `nonPositive(rung)`.
   - Present anchors must be non-decreasing in rung order. The first violating pair gives `outOfOrder(lower:upper:)`.
   - Equal adjacent anchors are allowed.
   - An empty ladder is valid.
2. **Derived fair:**
   - Applies only if at least one of buyLow or buyHigh is present **and** fair, trim and sell are all absent.
   - `derivedFair = (buyHigh ?? buyLow) * 10 / 7`. Never write it as `Decimal(0.7)`.
   - It counts as `fair` for both the knots and the status.
3. **Knots:**
   - One knot `(price, score)` per present anchor, plus the derived fair if any.
   - Tails: `(0.5 × lowest, 0)` and `(1.5 × highest, 100)`. "Highest" includes the derived fair.
   - Stable sort by price.
4. **Temperature:**
   - `nil` if there are no anchors.
   - Below the first knot, use its score (0). Above the last knot, use its score (100).
   - Otherwise interpolate linearly on the **first** segment `[x0, x1]` with `x0 ≤ p ≤ x1`. If `x0 == x1`, use `y0`.
   - Compute in `Double`.
5. **Status:** compare as `Decimal` and return the first rule that matches:

   | Condition | Status |
   |---|---|
   | sell present and p ≥ sell | `SELL` |
   | trim present and p ≥ trim | `TRIM` |
   | effective fair present and p ≥ effective fair | `AT_OR_ABOVE_FAIR` |
   | buyLow present and p ≤ buyLow | `DEEP_BUY` |
   | buyHigh present and p ≤ buyHigh | `BUY_ZONE` |
   | otherwise | `WATCH` |
   | ladder is empty | `NO_ANCHORS` |

6. **Distance to buy:** `(buyHigh − p) / p × 100`, or `nil` if buyHigh is absent. The UI shows "in band" when the result is ≥ 0.

### 7.3 Alert rule (`shouldAlert`, server only, plan 06)
`shouldAlert(previous: LadderStatus | null, next: LadderStatus) -> boolean`, with `rank` as DEEP_BUY = 0, BUY_ZONE = 1, WATCH = 2, AT_OR_ABOVE_FAIR = 3, TRIM = 4, SELL = 5:
- `previous == null` or `next == previous`: `false`. A null previous seeds the status without a push.
- `next ∈ {DEEP_BUY, BUY_ZONE}` and `rank(next) < rank(previous)`: `true`.
- `next ∈ {TRIM, SELL}` and `rank(next) > rank(previous)`: `true`.
- Anything else: `false`.
- `NO_ANCHORS` never alerts. Items without anchors are not evaluated.

### 8.4 Endpoints
**Request rules:**
- Every route except `register`, `/health` and `internal/*` requires `Authorization: Bearer <jwt>`.
- Prices are decimal strings. Times are ISO 8601 UTC from `Date.prototype.toISOString()` (millisecond precision).
- **Market** endpoints accept only US symbols: `^[A-Z]{1,5}([.-][A-Z]{1,2})?$` (`SYMBOL_REGEX` in `schemas/common.ts`).
- **Sync** accepts a wider pattern, `^[A-Z0-9][A-Z0-9.-]{0,14}$`, so legacy HK/OTC items can still sync (plan 05).

- The iOS backend adapter drops non-market symbols before calling `/api/market/quotes` (plan 04).

### 8.5 Sync protocol (plan 05)
**Server: `WatchlistSyncService.sync(userId, { cursor, changes }, now)`**
1. Validate every change: `domain/ladder.ts validateLadder` plus the size limits.
2. Clamp `clientUpdatedAt` to at most now + 5 min.
3. **Push**, but only if there are changes, as one statement:
   - The CTE runs `UPDATE users SET watchlist_version = watchlist_version + 1 … RETURNING` to get `v`.
   - It then does `INSERT … SELECT FROM jsonb_to_recordset($changes) … ON CONFLICT (user_id, symbol) DO UPDATE … WHERE w.client_updated_at < EXCLUDED.client_updated_at RETURNING symbol`. On a tie, the server's copy wins.
   - Deletes set `deleted_at = now`.
   - If the anchors changed, `last_status` resets to NULL, so the next daily run records the status without a push.
4. `applied` is the set of symbols returned. `rejected` is the set of sent symbols minus `applied`.
5. **Pull:** `WHERE user_id=$1 AND (version, symbol) > ($v, $s) ORDER BY version, symbol LIMIT 500`. Also add the **current rows for `rejected` symbols**, deduplicated by symbol.
6. Respond with `{ changes, cursor: "<version>:<symbol>" of the last pulled row (or the input cursor if none), hasMore: pulled.length === 500 }`. The initial cursor is `null`, which means `(0, '')`.

**Client: `SyncEngine`** (an actor, single-flight; it runs once more if a sync was requested while one was in flight)
- **State:** `SyncState` is stored in the app group at `sync-state.json`:
  `{ cursor: String?, acknowledged: [String: Date], tombstones: [String: Date], lastSyncedAt: Date? }`
- **Pending changes** are:
  - items where `acknowledged[symbol] != item.updatedAt`
  - tombstones where `acknowledged[symbol] != tombstoneDate`

  This covers the first upload with no special case: after a migration, `acknowledged` is empty, so everything is pushed.
- **Steps:**
  1. POST `{ cursor, changes: pending.prefix(200) }`.
  2. On 200, set `acknowledged[symbol] = sentStamp` for every change that was sent.
  3. For each remote row `r`, let `local = max(item.updatedAt, tombstone)`.
     - `local` is nil or `r.clientUpdatedAt > local`: apply `r` (upsert, or delete and record a tombstone if `r.deleted`), and set `acknowledged = r.clientUpdatedAt`.
     - The two are equal: set `acknowledged`.
     - `r.clientUpdatedAt < local`: keep the local copy, which stays pending.
  4. Store the new `cursor`.
  5. Loop while `hasMore` (with `changes: []`) or while pending changes remain, at most 10 rounds.
  6. Set `lastSyncedAt`.
- **Triggers:** launch or becoming active, a 2 s debounce after any watchlist change, and pull-to-refresh.
- **Account:** deleting the account resets `SyncState`.
- **Re-adding** a symbol clears its tombstone, and the new `updatedAt` is newer than the tombstone.
- **Every stamp is truncated to milliseconds** (D21).

### 8.6 Daily alert job (plan 06): `AlertJobService.run(now)`
1. `tradingDate` = the America/New_York date of `now`. Saturday or Sunday returns `skipped`.
2. `INSERT alert_job_runs(trading_date,'running') ON CONFLICT DO NOTHING`. If the run for that date is already `completed`, only re-send pending events (step 9) and return `resent`.
3. Load the live items that have at least one anchor (`deleted_at IS NULL`).
4. Make one Massive grouped-daily call (`/v2/aggs/grouped/locale/us/market/stocks/{date}?adjusted=true`) behind `tryTake("provider:massive")`.
5. If the result is empty, fetch a Finnhub quote for `SPY` and compare its date (`t`, converted to ET) with `tradingDate`. If they differ, mark the run `holiday` and return. If they match, the data just isn't published yet: continue with the fallback.
6. Symbols missing from the grouped data are fetched from Finnhub, at most 25. A price is used only if its `t` falls on `tradingDate`.
7. For each item, `next = classifyStatus(ladder, close)`:
   - `last_status IS NULL`: seed it, no event.
   - `shouldAlert(last_status, next)`: create an event.
   - **Split guard:** if `|close / last_evaluated_price − 1| > 0.5`, update the status but create no event, and log it.
8. Bulk-insert events with `INSERT … SELECT FROM jsonb_to_recordset … ON CONFLICT (user_id, symbol, trading_date, status) DO NOTHING RETURNING id`.
9. Bulk-update `last_status`, `last_status_at` and `last_evaluated_price` with `UPDATE … FROM jsonb_to_recordset`. This does **not** bump `version`.
10. Send every event with `sent_at IS NULL AND trading_date = $d AND attempts < 3` to all of the user's devices.
    - Success: set `sent_at`.
    - Failure: increment `attempts`.
    - A user with no devices: set `sent_at` and count the event as skipped.
11. Mark the run `completed` with its stats.

**Idempotency:** a crash after step 8 or step 9 is safe to rerun: the inserts do nothing on conflict, and pending events are still sent.

**Duration:** about 1 Massive call, about 1 SPY call, at most 25 fallback calls, bulk SQL, and one HTTP/2 session. That is well under 10 s, and the job must not need `maxDuration`, which the legacy `builds` config can't set.

**Schedule:** `vercel.json` gets `"crons": [{ "path": "/api/internal/daily-alerts", "schedule": "0 22 * * 1-5" }]`, with the existing `builds` and `routes` kept.

### 8.7 APNs (plan 06)
- **Provider token:** ES256 JWT.
  - Header `{ alg: "ES256", kid: APNS_KEY_ID }`, claims `{ iss: APNS_TEAM_ID, iat }`.
  - Signed with `crypto.sign("sha256", input, { key, dsaEncoding: "ieee-p1363" })`.
  - Cached for at most 50 min.
- **Transport:** one `node:http2` session per host, `api.push.apple.com` or `api.sandbox.push.apple.com`.
  - Request: `POST /3/device/<token>`.
  - Headers: `authorization: bearer <jwt>`, `apns-topic: com.chenkai.wait`, `apns-push-type: alert`, `apns-priority: 10`, `apns-collapse-id`.
  - Timeout: 10 s.
- **Payload:**
  ```json
  {"aps":{"alert":{"title":"AAPL · BUY ZONE","body":"Closed $172.10, at or below buy-high $175.00 · 27°"},"sound":"default","thread-id":"AAPL"},
   "symbol":"AAPL","status":"BUY_ZONE","deepLink":"wait://stock/AAPL"}
  ```
  The collapse id is `"<SYMBOL>-<tradingDate>"`.
- **Responses:**

  | Response | Action |
  |---|---|
  | 200 | Set `last_success_at` |
  | 410, or 400 `BadDeviceToken` / `DeviceTokenNotForTopic` | Prune the token, but only if its stored `environment` matches the host it was sent to |
  | 403 `ExpiredProviderToken` | Invalidate the provider token and retry once |
  | 429 or 5xx | Retry once after 1 s |

- **iOS:** the device environment is `sandbox` under `#if DEBUG` and `production` otherwise (TestFlight counts as production). A tap on the push opens the `DeepLink.stock(symbol)` from the payload's `deepLink`.

## 9. iOS ↔ server wire conventions
- **JSON:** camelCase keys. Prices are decimal strings. `changePercent`, `temperature` and the ratios are numbers.
- **Dates:** ISO 8601 UTC with milliseconds (`2026-11-20T21:00:00.000Z`).
  - Swift encodes with `Date.ISO8601FormatStyle(includingFractionalSeconds: true)`.
  - Swift decodes with a strategy that accepts both the fractional and the non-fractional form.
- **APIClient** (plan 04):
  - Base URL comes from Info.plist `WaitAPIBaseURL`.
  - The JWT is kept in memory only. On first use, the client registers with `IdentityClient.anonymousID()`.
  - On a 401, it re-registers once and retries the request once.
  - A 429 or 503 maps to `MarketDataError.rateLimited(retryAfter:)`.
- **Keychain:** service `com.chenkai.wait`, account `anonymous-id`, `kSecAttrSynchronizable = true`, `kSecAttrAccessibleAfterFirstUnlock`. Every query sets `kSecAttrSynchronizable` explicitly.
- **Deep links:** `wait://stock/<SYMBOL>`. The URL scheme `wait` is registered in the app's Info.plist in plan 02. Widget rows use it.
- **App group:** `group.chenkai.wait.contents`. Files: `watchlist.json`, `checklist-template.json`, `snapshot.json`, `sync-state.json` (05), `migration-v1.done`.
  - Plan 02 adds the app group to the **Debug and Release** entitlements of both the app and the widget.
  - Persistence falls back to Documents when `containerURL` is nil, which happens in package tests and unsigned builds.

## 11. Risk register
1. **TCA 1.26 needs swift-tools 6.1, so Xcode ≥ 16.3.** Bitrise must move to that stack. The baseline under Xcode 27 may fail inside TCA 0.31 or Shake 14; plan 01 Task 1 records the fallback.
2. **CLI builds need `-skipMacroValidation`** for the TCA, CasePaths, Dependencies and Perception macros. Add `-skipPackagePluginValidation` as well, in local commands and in Bitrise.
3. **Swift 6 strict concurrency:**
   - A `static let` holding a non-Sendable value (`DateFormatter`, `JSONDecoder`, `UIColor`) is an error. Use `.formatted()` styles or local instances.
   - `@DependencyClient` closures must be `@Sendable`.
   - Delegate classes (`WCSessionDelegate`, `UNUserNotificationCenterDelegate`) need explicit isolation.
   - Effects report back through paired success/failure actions, never `Result<_, any Error>`.
4. **TCA 1.x idioms:**
   - Views use `@Bindable var store` or `let store`. `WithViewStore` is gone, and `WithPerceptionTracking` isn't needed on iOS 17.
   - A `@Reducer enum` State needs `extension …State: Equatable {}`.
   - Debounce through `clock.sleep` plus `.cancellable(id:cancelInFlight:)`.
5. **`@Shared(.fileStorage)` writes are throttled:**
   - Save explicitly when the scene goes to the background.
   - Shared values must be Codable and Sendable.
   - Mutate through `withLock` (inside the Persistence helpers).
   - Isolate tests with `.dependencies` traits.
6. **Decimal precision:** `JSONDecoder` routes numbers through `Double`. Encode decimal strings, round legacy values to 4 decimal places, never write `Decimal(0.7)`, and add round-trip tests (3.133, 0.0075).
7. **Date bugs:**
   - `yyyy-mm-dd` parses minutes into the month position. Use `yyyy-MM-dd` with `en_US_POSIX` and an explicit time zone.
   - Twelve Data returns exchange-local times unless `timezone=UTC` is sent.
   - Legacy files must be decoded with `deferredToDate`.
8. **Twelve Data stopgap:**
   - It allows 8 credits/min, so lists with more than 8 symbols fill in over several minutes.
   - Rate limits arrive as HTTP 200 with `code: 429` in the body.
   - Errors are reported per symbol.
9. **Keychain synchronizable:**
   - It only syncs when iCloud Keychain is enabled, and needs `AfterFirstUnlock`.
   - Every query must include `kSecAttrSynchronizable`.
   - A second device may create its own ID before sync arrives.
   - Package tests get `-34018`, so always mock `KeychainClient`.
   - Surviving a reinstall is observed behavior, not a documented guarantee.
10. **APNs:**
    - The signature must be raw `r‖s` (`ieee-p1363`).
    - The provider token is valid for 20–60 min.
    - A sandbox/production mismatch looks like `BadDeviceToken`, which is why pruning checks the environment.
    - `apns-push-type` is mandatory.
    - A multiline PEM stored in an env var must be normalized.
11. **Vercel:**
    - Hobby cron runs once a day, ±59 min, in UTC, on production only.
    - Cron Jobs are being labeled "legacy" in favor of Schedules, which need `functions` (incompatible with `builds`).
    - There's no `maxDuration` with `builds`.
    - Root Directory must be `server`.
    - Register is open to anyone; the IP bucket and caches limit abuse.
12. **Massive free tier:**
    - The time end-of-day data gets published is undocumented. The SPY date check tells a holiday apart from "not yet published".
    - `MASSIVE_BASE_URL` is configurable.
    - The job makes exactly one Massive call.
13. **PGlite vs Neon:** parameter serialization can differ. The optional `npm run test:neon` runs the repository suite against a Neon branch (`TEST_DATABASE_URL`).
14. **Clock skew:** client timestamps are clamped to now + 5 min, and ties go to the server. A device whose clock is far ahead can still win conflicts it shouldn't. Documented and accepted.
15. **Splits:** the split guard skips an alert when the price moves more than 50%, but anchors are not adjusted. The UI can suggest re-anchoring.
16. **App group migration:**
    - Runs once at the first launch after the update, keeps the old files, and writes a marker.
    - Old Debug builds had no app-group entitlement.
    - The widget shows a placeholder until the first snapshot is written.
17. **Watch:**
    - Bundle id must be `com.chenkai.wait.watchkitapp`, with companion `com.chenkai.wait`.
    - Once embedded, a watch build failure breaks the app build.
    - WCSession needs paired simulators (`xcrun simctl pair`).
    - Application context is latest-wins and capped at about 65 KB.
    - Read `receivedApplicationContext` at launch.
18. **Widget:**
    - iOS 17 requires `containerBackground(for: .widget)`.
    - The widget has no network access, so its freshness depends on the app publishing snapshots.
19. **Bitrise:** the config lives outside the repo. Update it by hand:
    - Xcode stack ≥ 16.3 (27 preferred).
    - Add `-skipMacroValidation`.
    - Use the new destination names.
    - The `Color` scheme is gone.
    - Package tests run through the `WaitKit-Package` scheme.
    - Add a server step: `npm ci && npm run typecheck && npm test`.
    - Add `scripts/check-secrets.sh`.
20. **Tooling:**
    - SwiftFormat isn't installed. Plan 03 bumps `--swiftversion` to 6.0.
    - Add `Packages/WaitKit/.build` and `.swiftpm` to the SwiftLint `excluded` list.
21. **XcodeGen discipline:**
    - Hand edits to the pbxproj are lost on regeneration.
    - Confirm `Wait.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved` survives each regeneration.
    - Gitignore `Packages/WaitKit/Package.resolved`.
22. **Secrets in git history:** rotate them (§10).
23. **Licensing:** the data is personal-use only (§6.4).
24. **Coverage:** HKEX and OTC symbols aren't covered. Existing HK items show "No quote", and the alert job skips them.
25. **Charts:**
    - `chartXSelection` returns raw values; snap them to the nearest index.
    - `AreaMark` needs an explicit `yStart` equal to the domain's lower bound.
    - Never build a Y domain from zero points (the existing crash).
26. **Startup order:** `@UIApplicationDelegateAdaptor` creates the delegate before the `App` body runs. The migration therefore runs inside the AppDelegate's lazy store initializer.
27. **xcconfig URLs:** write them as `https:/$()/host`. A local `http://localhost:3000` needs `NSAllowsLocalNetworking` in Debug.
28. **Legacy quirks:** duplicate symbols and `"Empty"` rows exist on disk. The old "favorite" really meant "on the watchlist".
29. **Server cache stampede:** concurrent instances may both miss the cache. In-process coalescing plus the token buckets bound the cost. Accepted.
30. **Vercel Schedules migration:** tracked, not adopted.
31. **Millisecond truncation (D21):** if any persisted or synced timestamp keeps sub-millisecond precision, the item can be re-pushed forever. The `WatchlistItem` mutation helpers truncate, and there is a test for it.
32. **Stale shared test vectors:** the TS and Swift suites both read `shared/ladder-test-vectors.json`. Changing it requires both suites to pass in the same commit.

**TCA `onChange` rule (all plans):**
- `.onChange(of:)` only sees mutations made by the reducer it wraps.
- Triggers that watch child state, such as AppFeature's snapshot publish on `\.watchlist.snapshotInputs` and plan 05's sync debounce on `\.watchlist.items`, must therefore wrap the whole composition:
  ```swift
  var body: some ReducerOf<Self> {
    CombineReducers {
      BindingReducer()
      Scope(...)
      Scope(...)
      Reduce { ... }
    }
    .onChange(of: \.watchlist.snapshotInputs) { ... }
  }
  ```
- `@Shared` writes made outside the reducer bypass `onChange`. Two cases:
  - Plan 05's `SyncEngine` merging remote rows. Fix: AppFeature also publishes the snapshot on `.syncFinished` when `report.pulled > 0`.
  - Plan 06's alert status updates. These live on the server only, so no client publish is needed.
- `.run` closures capture dependencies explicitly, e.g. `.run { [clock, syncClient] send in … }`. Reducers are public structs and are not implicitly Sendable.
